# 终稿自查清单

> 何时读本册:write 完稿后(阶段五)逐项执行;review 用它逐组检查,按文末「审阅报告」的格式交付;revise 从文末「改稿路径」进入,改完再按清单复查。清单按七组组织;括号内 S/C/G 编号指向 `sentence-patterns.md` / `concept-introduction.md` / `visual-figures.md` 的对应条目。执行方式:逐项打勾,不许只扫一遍;任何一项不过,回到对应分册修,再回来复检。
>
> 按规模取用:标 ▲ 的是长文与系列专属项,短文、中篇跳过;以「系列:」开头的项只在系列里查;对话级只查 SKILL.md「规模分档」里的四项。优先级:六组(诚实与归属)的非 ▲ 项是硬约束,必须全过;其次是二、三组(结构、概念与术语);四、五组的节奏与图注细项可按篇幅放宽。

## 一、契约与路线图

- [ ] 读者画像写成了概率化句(S14);域外知识从零科普,前置词汇只使用不定义?
- [ ] 选定了两门参照系,核心概念尽量双通道映射(S34/S35),映射牵强处宁缺?每个具体锚点只映射一个概念,没有拿同一个锚点解释两件事?
- [ ] 坐标系(2–3 个正交轴)在最前面标出,并被后文枚举复用?
- [ ] 有摘要位时,摘要恰好两句:领域事实句 + 双动词动作句,零数字零结论(S12)?没有摘要位时,开头第一段完成了钩子与路线图?
- [ ] 路线图只承诺承重主干(支线与尾声不计数,S17);写完正文回头逐条兑现?
- [ ] ▲ 坡度承诺(S18)与实际难度曲线一致——没有中途偷偷跳级?
- [ ] 系列:每篇开头用一两句接上篇的出口(不重讲上篇;首篇改为一句话交代整个系列),篇尾给下篇留了钩子?只读这一篇的读者也能跟上:首次用到前面篇章定义的术语,旁边补了半句提醒?

## 四、句式与节奏

- [ ] 情态词定岗未换岗(can=能力、might=愿望、could=想象、would=提案、often=频率)?
- [ ] 长句没有扎堆(连写两个长句后换短句或换段)?每个短句都担着一个岗位(引图/转折/命名/判决/推广/路标)?段落 1–3 句?
- [ ] 主语分工:机制句以对象为主语;we 管操作与回顾;you 只用于猜心思/点需求/下指令?
- [ ] 全文恒现在时(机制与示例)?被动态只用于「与施动者无关」的能力句?
- [ ] 枚举用冒号开清单;长句用 where/which 分层而非破折号分号?
- [ ] 评价副词(Fortunately/Unfortunately/surprisingly 一类)一篇一两个,且前置?
- [ ] 观察指令(Note that… / The first thing to notice is…)只出现在第一次读图读数据、坦白简化、节尾自曝与换挡处,没有到处撒?
- [ ] 中文稿:没有照英文语序直译骨架?没有「被」字句顶替被动、没有满篇「我们可以」?逗号流水链和「的」字链拆开了(sentence-patterns.md 中文适配)?

## 六、诚实与归属

**经验结论的校准**

- [ ] 每条经验趋势同句配反例(S39)?统计结论带统计性主语「平均/下界」(S42)?
- [ ] 被问「哪个最好」时先答「无一致最优」再讲各自适用场景(S40)?
- [ ] 多组结果打架时直说 mixed messages,并拎出唯一站得住的趋势(S41)?
- [ ] 你答不了的问题用开放问题句式 + 引用收尾(S43),没有含糊措辞伪装成答案?
- [ ] 教学简化自己拆穿:「实践中其实…」的落差声明(S44)都跟在简化引入后的短窗口内?
- [ ] 坏消息配括号让步、好消息配条件从句(S45),稀缺使用?
- [ ] 开篇的时间层次、「近期进展」和收束的机会从句都有真实依据?常青主题没有被硬写成「此刻正在发生」?

**归属记账**

- [ ] 每条引用都真实可查?拿不准的标了「[待补引用:…]」,没有编造作者、年份、标题或数字?
- [ ] 引用与被归属的术语物理相邻(S46),不用「某某等人提出了」从句?
- [ ] 归属动词按贡献分级:提出框架 proposed by / 提供图示 introduced by / 发展想法 developed with / 是某工作的基础 is the basis of(S47)?
- [ ] 并举例证逐例挂引,没有一条引用兜底整串?可被质疑的断言(年限、经典性)有引用贴身作保?
- [ ] 延伸阅读类引用降级进括号(see …),与论证类引用版式区分?
- [ ] ▲ 引用密度按章节功能分配:教学主干每段至多一引,综述/容器可密集——密度本身是「这里是导览、那里是前沿」的信号?
- [ ] 借用或改编的图示记了谱系(基于谁的体系、谁制作、何种许可):长文与系列写进致谢,短文、中篇写在图注里?

## 七、收束与回环

- [ ] 收束四件套齐全:回环句(复现开篇对比框架,S48)+ 降格回顾(outlined/walked through + some of)+ 资产复指(演示/练习复指为读后仍可用的直觉工具)+ 开门句(机会从句+情绪从句,S49;常青主题见本组第三项)?
- [ ] 没有 In conclusion 套话、没有复述路线图编号、没有列要点、没有文末单设的「局限」一节——局限都在出现处就地交代了?
- [ ] 末句向前看:有真实的新进展时以 we + 情感动词展望、落到具体的新问题上,与开篇的 we 呼应;常青主题以可动手的下一步或开放问题收尾?
- [ ] 「下一步」是可动手的实验与开放问题,不是阅读清单?进阶出口内联设在需求产生的那一句,而不是堆在文末?

## 审阅报告(review 的交付格式)

review 只诊断、不改稿。报告用作者读得懂的话写,按症状和读者效果陈述,不引规则编号(用户要求时才附分册出处)。分五块:

1. **总评**(3–5 句):这篇写给谁、想讲清什么;最值得保留的一点;最要紧的一到三个问题;结论三选一:可以发布 / 小改后发布 / 需要重构。
2. **问题清单**,按对读者的影响排序。每条写三行:
   - **症状**(阻断/重要/次要):读者在哪里会掉队、误解或不信;
   - **位置**:小节与段落序号,或用「」引出原句的开头;
   - **改法**:具体到动作(「把定义挪到第二个例子之后」);阻断级和重要级各附一小段示范改写(一到三个短句)。建议作者新加类比时,连它哪里不像一起写出(半句就够)。
3. **值得保留**(2–4 条):好的例子、准确的类比、作者自己的声音——改稿时别动。
4. **事实与引用待核**:逐条列出拿不准、说得过宽或缺出处的说法,写明为什么存疑,不下结论;没有就写「未发现」。确知的错误不放这里,作为阻断项写进问题清单,并给出正确说法。
5. **体检表**(中篇及以上附上):七组各一行,结论写 通过 / 部分 / 未过 / 不适用,附一句依据。

严重度:
- **阻断**:不改,读者就读不下去或会被误导——问题链断了、定义先于缺口、事实错误。
- **重要**:读者会吃力或起疑——缺最小例、类比没写断点、术语漂移、趋势没配反例。
- **次要**:只影响读感——句子节奏、过渡重复、个别措辞。

破折号后列的是常见情形,不是自动定级:定级看这一处在这篇稿子里的实际后果。比如几百字的短稿开头先下定义,读者多半还读得下去,记为重要即可。

结论怎么定:有结构性的阻断(问题链断了、定义先于缺口、一段倒出几种机制)→ 需要重构;阻断只在事实或个别句段,或者没有阻断、只有重要项 → 小改后发布;只剩次要项 → 可以发布。

条数随篇幅:对话级至多 3 条,短文 6 条,中篇 8 条,长文 12 条,「其他」也算一条。超出时先把同一根因的问题并成一条,按其中最重的一项标严重度;还超,就把次要问题并进「其他」,举两三个例子。阻断和重要项不能为凑条数删掉,合并后仍超就超。系列逐篇审,另加一条跨篇问题(术语漂移、上下篇衔接)。

报告末尾可以加一行交付说明(按哪一档审、用了哪些默认值),不算在五块里。

## 改稿路径(按症状查;review 与 revise 共用)

括号里的编号指向分册条目,写示范改写或动手改稿时再去查。

| 症状(读者反馈或原稿问题) | 先查 |
|---|---|
| 读者读到一半迷路 | 二组:问题链、钩子回收;每组出口是否留了未答问题 |
| 读者说「太抽象/跟不上」 | 三组:缺口句、最小可操作例、抽象承诺是否兑现;一组:双锚落地;长文再查一组 ▲ 坡度承诺 |
| 术语越读越糊 | 三组:别名收编、三级标记、重述链;全文 grep 同义词 |
| 结论被读者质疑 | 六组:趋势配反例、统计性主语、无一致最优、归属记账 |
| 文章「哪都对但没记忆点」 | 一组:反直觉预告(S15/S16)、首屏演示(G1)、回环(S48) |
| 图看不懂/与正文脱节 | 五组:图注自包含、指示句、视觉记号冻结 |
| 结尾乏力 | 七组:四件套;主线收尾的方向段(structure-templates.md 段 6) |
| 篇幅超载 | 先砍深水区容器与支线,再按逃逸舱五分诊(concept-introduction.md)分流——展开欲超过一句就是推送信号;主线的例子与类比断点最后才动;对话级没有容器可送,直接删,再用一句「这里没讲 X」交代 |
| 原稿开头就是词条式定义(「X 是一种……的……」) | 三组:先造缺口再命名(C1/C2/S6),首现嵌进旧词主句(concept-introduction.md 术语规则 1);范畴词先举例后命名(S9) |
| 原稿一段里并列倒出多种方法或机制 | 二组:棘轮每级只加一个机制;分类族用报数总起 + 同构排比(S10);不在主线上的变体压成一句旁注(C7) |
| 原稿通篇没有例子 | 三组:最小可操作例(C6),小到能穷举、能心算;句式见 S29/S32 |
| 原稿有事实错误或说法过宽 | 六组;SKILL.md「交付约定」:revise 指出并修正,列进「请核实」清单,不悄悄改;review 把确知的错误列为阻断并给出正确说法,拿不准的放进待核 |
| 读起来像翻译 | 四组中文项;改用 sentence-patterns.md 每条的中文骨架与文末「中文适配」 |
| 不知道改稿该交付什么 | SKILL.md「交付约定」:改后全文 + 至多 5 条按症状写的改动说明 + 单列的「请核实」清单;保留作者的事实与立场 |

## 快速小抄(打印版)

1. 顺序 = 读者的下一个问题,不是学科的章节。
2. 每步一个机制,增量点名三遍,缺陷链推进。
3. 没有缺口就没有名词;一支术语表不换口径。
4. 体验先于术语;抽象承诺当场兑现,或写明在哪兑现。
5. 类比必带断点;反常识显式命名并预付回报。
6. 趋势同句配反例;答不了就写开放问题;引用必须真实可查。
7. 图注给答案和指令,永不设问;简化必披露。
8. 收束 = 回环 + 降格回顾 + 资产复指 + 开门。
